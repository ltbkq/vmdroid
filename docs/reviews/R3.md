## Blocker（1 条，已修）

### RB-3-1（B-R3-1）· 恢复出厂判据方向性错误
- **位置**：DESIGN §4.3
- **问题**：我写的"清零首个 1 MiB → guest mkfs"**是错的**：4 KiB 块布局的
  **备份超级块在 block 32768 = 128 MiB 处**，只清头部时 `e2fsck` 会回退修复
  （`Superblock invalid, trying backup blocks...` → **rc=1**），并把主超级块写回首部 →
  此后 `rc≥8 && 全零` 与 `rc≥4` 两个分支**都不满足** → **静默不 mkfs，恢复出厂无声失效**。
- **依据**：评审者本地 e2fsprogs 1.47.0 实测（`truncate -s 8G` + `mkfs.ext4` + 真实布局）：
  只清首 1 MiB → rc=1、首 1 MiB 被回写非全零、`/marker` 数据仍在、第二次 mount 成功；
  整文件清零 → rc=8 + 全零 → **mkfs ✔**。上游 `init-podroid:60-75` 源码注释核对一致。
- **修复**：§4.3 改为**整文件清零**（`setLength(0)` + `setLength(size)`），
  写明反例与实测数据；补**隐私**条款（部分清零+mkfs 残留旧数据块）；
  补 **initramfs 待验证项**（`cpio -t` 查 e2fsprogs vs BusyBox e2fsck —— 退出码语义不同）。
- **连带修正**：DESIGN §4.3 表格行、`factory_reset` 事件 `method=whole-file-zero`。
